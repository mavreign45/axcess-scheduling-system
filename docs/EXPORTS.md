# Axcess export reference

Axcess provides four authenticated export endpoints. Excel exports are genuine Office Open XML `.xlsx` workbooks generated by Maatwebsite/Excel and PhpSpreadsheet. CSV is an explicitly separate single-sheet format and is never given an `.xlsx` name.

## Endpoints

| Export | Route | Format |
| --- | --- | --- |
| Schedule / operational workbook | `GET /exports/schedule` | `.xlsx`, `.csv` |
| Staff directory | `GET /exports/staff` | `.xlsx`, `.csv` |
| Leave & absences | `GET /exports/leave` | `.xlsx`, `.csv` |
| Management reports | `GET /exports/reports` | `.xlsx`, `.csv` |

Every route is behind the `auth`, `active`, and `can:export-data` middleware. Administrators and managers can download exports; employees receive `403`.

The browser dialogs submit these GET requests with `fetch`, read the binary blob, and trigger a download using the server filename. Successful downloads are recorded in `export_logs` with the user, type, format, filters, filename, and primary-row count.

## Common parameters

| Parameter | Values | Notes |
| --- | --- | --- |
| `format` | `xlsx`, `csv` | Multi-sheet exports require `xlsx`. |
| `mode` | `date`, `week`, `month`, `custom` | Period mode. |
| `date` | `YYYY-MM-DD` | Used by `mode=date`. |
| `week` | `YYYY-MM-DD` | Any date in the desired ISO week; the week runs Monday–Sunday. |
| `month` | `YYYY-MM` | Used by `mode=month`. |
| `from`, `to` | `YYYY-MM-DD` | Used by `mode=custom`; inclusive. |
| `department_id` | integer | Managers are always forced to their own department. |
| `user_id` | integer | Must belong to the selected/authorized department. |
| `include_sensitive` | `0`/`1` | Adds confidential reasons/notes for authorized managers and admins. |
| `format` | `xlsx` or `csv` | Defaults to `xlsx` on the server. |

Period ranges are capped by `AXCESS_EXPORT_MAX_RANGE_DAYS` (default 366 days). Reversed or invalid ranges produce a validation error; they do not silently return an empty file.

## Schedule workbook (`/exports/schedule`)

### Schedule-specific filters

| Parameter | Values |
| --- | --- |
| `shift_type_id` | Any active shift type |
| `status` | `draft`, `published`, `confirmed`, `completed`, `cancelled` |
| `standby_only` | `0`/`1` |
| `worksheets[]` | Any of `schedule`, `staff_summary`, `breaks`, `leave_absences`, `standby_replacements`, `conflicts` |

Example:

```text
/exports/schedule?format=xlsx&mode=custom&from=2026-10-19&to=2026-10-25
  &department_id=1&status=published
  &worksheets[]=schedule&worksheets[]=staff_summary&worksheets[]=breaks
  &worksheets[]=leave_absences&worksheets[]=standby_replacements&worksheets[]=conflicts
```

### Requested worksheets

| Key | Worksheet title | Contents |
| --- | --- | --- |
| `schedule` | Schedule | One row per assignment, including standby and unassigned shifts |
| `staff_summary` | Staff Summary | Scheduled shifts/hours, breaks, net hours, standby, leave, absences, replacements; total formula row |
| `breaks` | Breaks | One row per break, with break number, label, start/end, minutes/hours, and parent shift times |
| `leave_absences` | Leave & Absences | Leave requests and absence records overlapping the period |
| `standby_replacements` | Standby & Replacements | Standby duties and replacement history |
| `conflicts` | Conflicts | Unresolved duplicate-free conflicts in the period |

Only selected worksheets are written. The default is `schedule`; if no valid worksheet is selected, the schedule sheet is used.

### Schedule columns

Without sensitive fields:

1. Schedule Date
2. Day of Week
3. Employee ID
4. Employee Name
5. Department
6. Job Position
7. Shift Type
8. Shift Start
9. Shift End
10. First Break Start
11. First Break End
12. Break Count
13. Break Summary
14. Total Scheduled (hrs)
15. Total Break (hrs)
16. Net Working (hrs)
17. Assignment Status
18. Standby Status
19. Replacement Employee
20. Overnight Shift

With `include_sensitive=1`, two columns are appended: **Replacement Reason** and **Manager Notes**.

### Overnight shifts and breaks

- A shift ending at or before its start is treated as ending the following day.
- Overnight rows use the **Overnight Shift = Yes** column and the next-day date/time in Shift End.
- Every break is preserved in both the Schedule sheet (`Break Count`, `Break Summary`, first break) and the Breaks sheet.
- Breaks after midnight are stored with their actual next-day timestamps; they are never folded into the shift date or dropped.
- Scheduled hours are the full elapsed shift time. Net hours = scheduled hours − all break hours.
- Formula-injection-safe text prefixes values that begin with `=`, `+`, `-`, `@`, tab, or carriage return with an apostrophe.

## Staff export (`/exports/staff`)

### Filters

| Parameter | Values |
| --- | --- |
| `employment_status` | `active`, `on_leave`, `inactive` |
| `standby_only` | `0`/`1` |
| `include_contacts` | `0`/`1` |

Columns: Employee ID, Full Name, Department, Job Position, Role, Employment Status, Employment Type, Hire Date, Standby Eligible, Maximum Weekly Hours, Account Status.

When `include_contacts=1`, Email and Phone are inserted before Hire Date. Passwords, remember tokens, password hashes, and authentication secrets are never selected or exported. Managers only receive staff in their own department.

## Leave export (`/exports/leave`)

### Filters

| Parameter | Values |
| --- | --- |
| `leave_type` | `annual`, `sick`, `personal`, `unpaid`, `maternity`, `paternity`, `bereavement`, `other` |
| `leave_status` | `pending`, `approved`, `rejected`, `cancelled` |
| `include_absences` | `0`/`1` (default `1`) |
| `include_sensitive` | `0`/`1` |

Worksheets:

- **Leave & Absences** — record type, employee, department, type, dates, duration, status, approver, approval timestamp, scheduling conflicts.
- **Leave Summary** — grouped by leave type and approval status with request/days totals and a `TOTAL` formula row.

With `include_sensitive=1`, Reason, Supporting Information, and Notes are appended for managers/admins. Without it, those fields are neither written nor referenced.

## Management reports (`/exports/reports`)

### `report_type`

| Value | Worksheets |
| --- | --- |
| `full` | All 11 worksheets |
| `staff_summary` | Overview, Staff Summary, Unassigned Shifts |
| `coverage` | Overview, Coverage, Unassigned Shifts |
| `breaks` | Overview, Break Coverage |
| `leave` | Overview, Leave & Absences, Leave Summary |
| `conflicts` | Overview, Conflicts, Unassigned Shifts |
| `replacements` | Overview, Standby & Replacements, Replacement History |

The full workbook contains:

1. Overview
2. Schedule
3. Staff Summary
4. Coverage
5. Break Coverage
6. Leave & Absences
7. Leave Summary
8. Standby & Replacements
9. Conflicts
10. Unassigned Shifts
11. Replacement History

Sensitive manager notes/reasons and leave reasons are included only when `include_sensitive=1`.

## Workbook layout and formatting

Each worksheet uses the same branded layout:

```text
Row 1  Axcess — Staff Scheduling & Workforce Management
Row 2  Worksheet/report title
Row 3  Reporting period
Row 4  Generated timestamp + author
Row 5  Active filter summary
Row 6  Bold teal header row (frozen, filterable)
Row 7+ Data rows
```

Formatting includes:

- a merged dark-slate title band and teal header fill;
- bold white header text;
- frozen panes at `A7`;
- AutoFilter over the header and data range;
- explicit column widths and wrapped note/summary columns;
- date (`yyyy-mm-dd`), date-time (`dd-mmm-yyyy hh:mm`), and decimal number formats;
- light row banding, print titles, landscape page setup, and an Axcess confidential footer;
- workbook properties (`creator`/`company` = Axcess, title, description);
- total rows using real Excel `SUM()` formulas where applicable.

## Filenames

The server sets a descriptive filename and MIME type:

```text
Axcess_Schedule_2026-10-19_to_2026-10-25.xlsx
Axcess_Staff_2026-10-22.xlsx
Axcess_Leave_2026-10-01_to_2026-10-31.xlsx
Axcess_Report_2026-10-01_to_2026-10-31.xlsx
Axcess_Schedule_2026-10-19_to_2026-10-25.csv
```

Schedule, leave, and report names include the resolved period. The staff export uses the generation date because it is a point-in-time directory.

## CSV behaviour

CSV is intentionally limited to the primary worksheet:

- schedule → Schedule rows;
- staff → Staff rows;
- leave → Leave & Absences rows;
- reports → Overview rows.

It is sent as `text/csv; charset=utf-8` with a `.csv` filename. The dialog warns that formatting, formulas, filters, and secondary worksheets are only available in Excel.

## Errors and empty results

- Invalid read-only filters return `422` JSON for JSON clients, or a redirect with validation errors for the browser dialog.
- Managers requesting another department receive `403`.
- Empty periods still produce a valid workbook with branded title rows and headers; there is no data row and no total row.
- Unexpected generation failures are logged and return a friendly message without exposing internal file paths or SQL.
- Export failures do not create an `export_logs` row.

## Security model

- Exports are never public: route middleware and request authorization both require `export-data`.
- Manager scope is enforced server-side in `ExportController::effectiveDepartment()` and `validatedUser()`.
- Employee selection is cross-checked against the selected department.
- Sensitive columns are opt-in and only for managers/admins.
- Staff exports never select password hashes, remember tokens, or authentication secrets.
- All user-controlled text cells are sanitised against spreadsheet formula injection.
- Export logs contain filter metadata only, never confidential note/reason text.
- Workbook contents are generated from scoped queries, not from client-supplied rows.

## Adding a worksheet

1. Add a data method to `App\Services\ExportDataService` returning `headings`, `rows`, `formats`, `widths`, and `wrap`.
2. Add the worksheet key to `App\Support\Axcess::SCHEDULE_WORKSHEETS` or the report type map.
3. Register a sheet builder in `ScheduleWorkbookExport` and/or `ReportsWorkbookExport`.
4. Add the key to the relevant Blade dialog and to the request's allowed values.
5. Add feature coverage for sheet names, empty results, sensitive columns, and formulas.
